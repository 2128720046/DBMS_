# 前端原型设计与页面功能清单

## 1. 先回答你的关键疑问：前端如何应对复杂查询？
结论：采用“按钮/表单 + SQL 指令”双模式。

原因：
- 纯表单可以覆盖大部分复杂查询（多条件、嵌套条件、排序、分页、分组筛选）。
- 但要覆盖“高度定制化、临时组合、批量脚本式操作”，仅靠表单不够高效。

推荐方案：
- 按钮/表单模式：处理简单到中等复杂度的增删改查和结构管理。
- SQL 指令模式：处理复杂查询、定制化批处理和临时高级操作。

关键约束：
- 前端不做 SQL 语义解析，不在浏览器端执行 SQL。
- 前端仅提供输入、基础校验、历史记录和结果展示。
- SQL 的解析、权限校验、执行和审计全部在后端完成。

## 2. 前端原型页面总览

### 2.1 登录页
功能目标：完成用户身份验证并进入系统。
主要功能按键：
- 登录
- 清空输入
- 记住账号（可选）

关键交互：
- 输入账号、密码。
- 登录失败时显示明确错误原因。

安全控制：
- 根据角色决定是否显示高危按钮（删除库、恢复备份、SQL 控制台）。

## 2.2 首页/仪表盘
功能目标：展示系统状态和快捷入口。
主要功能按键：
- 进入数据库管理
- 进入表管理
- 进入记录查询
- 检查后端健康状态

关键展示：
- 当前登录用户
- 当前选中数据库
- SQL 最近执行记录摘要（成功/失败、耗时）

## 2.3 数据库管理页
功能目标：实现数据库查、建、删。
主要功能按键：
- 刷新数据库列表
- 新建数据库
- 删除数据库
- 打开数据库

弹窗与表单：
- 新建数据库弹窗：数据库名称、存储路径（可选）
- 删除确认弹窗
- 快捷进入 SQL 控制台（自动带入当前数据库上下文）

对应接口：
- GET `/api/databases`
- POST `/api/databases`
- DELETE `/api/databases/{databaseName}`

## 2.4 表管理页
功能目标：在当前数据库下管理表结构。
主要功能按键：
- 刷新表列表
- 新建表
- 删除表
- 查看表结构
- 进入字段管理

弹窗与表单：
- 新建表弹窗：表名、字段列表、主键设置
- 表结构预览抽屉：字段、索引、约束总览

对应接口：
- GET `/api/databases/{databaseName}/tables`
- POST `/api/databases/{databaseName}/tables`
- DELETE `/api/databases/{databaseName}/tables/{tableName}`

## 2.5 字段管理页
功能目标：维护字段定义与约束信息。
主要功能按键：
- 新增字段
- 修改字段
- 删除字段
- 保存结构变更

字段项：
- 字段名
- 类型
- 长度
- 是否非空
- 是否唯一
- 默认值
- 是否自增
- 是否主键

高级功能按键：
- 批量导入字段定义（JSON）
- 一键生成默认约束模板

## 2.6 记录管理页
功能目标：完成数据增删改查。
主要功能按键：
- 条件查询
- 新增记录
- 批量更新
- 删除记录
- 导出查询结果（可选）

关键交互：
- 条件构造器（字段 + 运算符 + 值）
- 表格展示结果和分页

复杂查询增强：
- 支持条件组嵌套（AND/OR）
- 支持排序、分页、字段投影
- 支持查询模板保存与复用
- 支持“转 SQL”按钮，把当前条件转换为 SQL 草稿并跳转 SQL 控制台

对应接口：
- POST `/api/databases/{databaseName}/tables/{tableName}/records/query`
- POST `/api/databases/{databaseName}/tables/{tableName}/records`
- PUT `/api/databases/{databaseName}/tables/{tableName}/records`
- DELETE `/api/databases/{databaseName}/tables/{tableName}/records`

## 2.7 索引与约束管理页
功能目标：完成索引与完整性规则管理。
主要功能按键：
- 创建索引
- 删除索引
- 重建索引
- 查看索引
- 执行约束校验

对应接口：
- POST `/api/databases/{databaseName}/tables/{tableName}/indexes`
- GET `/api/databases/{databaseName}/tables/{tableName}/indexes`
- POST `/api/databases/{databaseName}/tables/{tableName}/constraints/check`

## 2.8 备份恢复页
功能目标：完成数据库维护能力。
主要功能按键：
- 立即备份
- 查看备份列表
- 恢复备份
- 删除备份

高危操作保护：
- 恢复备份前展示影响范围并要求二次确认。

对应接口：
- POST `/api/backup/{databaseName}`
- POST `/api/restore/{backupName}`

## 2.9 系统设置页（可选）
功能目标：集中管理配置。
主要功能按键：
- 修改后端地址
- 清理缓存
- 导出日志（可选）

## 2.10 SQL 控制台页（新增核心页面）
功能目标：承接复杂查询与定制化操作。

主要功能按键：
- 执行 SQL
- 格式化 SQL
- 清空编辑器
- 保存脚本
- 查看执行历史
- 终止执行（长查询）

主要区域：
- SQL 编辑器
- 参数输入区（可选）
- 执行结果区（表格/消息）
- 执行信息区（耗时、影响行数、错误详情）

对应接口（建议）：
- POST `/api/sql/execute`
- GET `/api/sql/history`
- POST `/api/sql/validate`（可选）

## 3. 从前端点击到后端执行的标准流程
1. 用户点击页面按钮。
2. 页面先进行前端参数校验。
3. 调用 `src/api` 请求函数。
4. 请求发送到后端 `controller`。
5. `controller` 调用 `application` 编排流程。
6. `application` 调用 `domain` 执行业务规则。
7. `domain` 调用 `infrastructure` 执行读写。
8. 返回 `ApiResponse` 给前端。
9. 前端渲染成功/失败提示并更新页面状态。

### 3.1 SQL 指令模式流程
1. 用户在 SQL 控制台输入语句并点击“执行 SQL”。
2. 前端执行基础校验（非空、长度、是否选择数据库）。
3. 前端请求 `POST /api/sql/execute`。
4. 后端 `controller` 接收 SQL 请求。
5. `application` 层做鉴权、审计、超时控制。
6. `domain` 层做 SQL 解析、规则校验与执行编排。
7. `infrastructure` 层读写数据文件并返回结果集。
8. 统一包装 `ApiResponse` 返回前端。
9. 前端展示结果表格或错误详情并记录历史。

## 4. 完整原型功能覆盖清单（项目全功能）
必须覆盖以下全部模块的“可操作页面入口”：
- 数据库管理：查、建、删、打开
- 表管理：查、建、删、结构查看
- 字段管理：增、改、删、约束配置
- 记录管理：查、增、改、删、导出
- 索引管理：建、删、查、重建
- 完整性管理：约束增删查、写入前校验
- 安全管理：登录、登出、权限提示
- 备份恢复：备份、恢复、列表、删除
- SQL 控制台：复杂查询与定制化操作

## 5. 第一轮可落地版本（最小可交付）
- 页面：登录页、首页、数据库管理页、表管理页、SQL 控制台页（基础版）。
- 交互：按钮模式打通数据库查建删；SQL 模式打通执行入口。
- 联调：健康检查、数据库列表、创建数据库、删除数据库、SQL 执行接口。
- 视觉：形成统一布局、按钮、表格、弹窗和错误提示规范。
