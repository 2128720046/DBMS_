# DBMS 后端模块化架构说明

## 1. 目标

本次重构把后端整理为“模块化单体”结构：仍然是一个 Spring Boot 应用，但代码按业务能力拆分。每个开发者只需要在自己负责的 `modules.<模块名>` 下开发，公共能力放在 `core`，HTTP 统一响应放在 `common`，从而降低多人协作时的包级冲突。

## 2. 总体目录

```text
com.dbms.backend
├── DbmsBackendApplication.java
├── common                       # 统一响应、错误码、全局异常
├── core                         # 跨模块基础能力
│   ├── capability               # 引擎功能开关与 SQL 白名单
│   ├── naming                   # 数据库名、表名、字段名校验
│   └── storage                  # 二进制文件存储配置与 IO 工具
└── modules
    ├── sql                      # SQL 控制台、解析与执行路由
    ├── database                 # 数据库创建、删除、列表
    ├── table                    # 表与字段定义管理
    ├── record                   # 记录增删改查
    ├── index                    # 索引扩展契约
    ├── integrity                # 完整性约束扩展契约
    ├── transaction              # 事务扩展契约
    ├── maintenance              # 备份还原扩展契约
    ├── security                 # 用户与权限扩展契约
    └── client                   # 客户端会话扩展契约
```

## 3. 模块职责

`common`
负责 `ApiResponse`、`ErrorCode`、`GlobalExceptionHandler`。所有 Controller 必须返回统一响应结构，不在业务模块里手写 HTTP 错误格式。

`core.naming`
负责标识符校验和规范化。数据库名、表名、字段名统一在这里校验，业务模块不重复写正则。

`core.capability`
负责引擎能力开关和 SQL 前缀白名单。后续如果某个模块暂未交付，可以通过配置关闭能力。

`core.storage`
负责 `StorageEngineConfig`、`StorageEngineProperties`、`BinaryIoUtils`。所有二进制文件读写工具集中在这里，避免各模块复制底层 IO 细节。

`modules.sql`
对外暴露 `/api/sql/execute`，完成 SQL 规范化、解析、执行路由和返回结构组装。它只编排，不直接读写数据库文件。

`modules.database`
负责数据库生命周期，对应 `CREATE DATABASE`、`DROP DATABASE`、`SHOW DATABASES`。当前实现读写全局数据库描述文件和库目录。

`modules.table`
负责表和字段定义，对应 `CREATE TABLE`、`DROP TABLE`、`ALTER TABLE`、`SHOW TABLES`、`DESC/DESCRIBE`。当前实现读写 `.tb`、`.tdf`、`.tic`、`.tid` 文件。

`modules.record`
负责记录 DML，对应 `INSERT`、`SELECT`、`UPDATE`、`DELETE`。当前实现根据 `.tdf` 解析字段布局，并读写 `.trd` 文件。

`modules.index / integrity / transaction / maintenance / security / client`
这些模块先提供验收要求对应的接口契约。后续开发者应在各自模块下新增 `application`、`controller`、`infrastructure`，不要把代码塞回 SQL、表或记录模块。

## 4. 关键接口

`DatabaseSchemaGateway`
创建数据库、删除数据库、列出数据库。由 `NativeDatabaseSchemaGatewayImpl` 实现，负责维护全局数据库描述文件和数据库目录。

`TableGateway`
创建表、修改表结构、删除表、列出表、读取表详情。由 `NativeTableGatewayImpl` 实现，负责 `.tb`、`.tdf`、`.tic`、`.tid` 的二进制格式落盘。

`RecordGateway`
插入、查询、更新、删除记录。由 `NativeRecordGatewayImpl` 实现，负责 `.trd` 记录文件读写。

`IndexGateway`
创建索引、删除索引、列出索引。后续实现应维护 `.tid` 和 `.ix`，并被查询执行器用于查询优化。

`IntegrityGateway`
保存约束、删除约束、校验待写入记录。后续实现应维护 `.tic`，并在记录插入/更新前被调用。

`TransactionManagerPort`
开启、提交、回滚事务。后续实现可结合日志、锁和临时文件完成单表或多表事务。

`MaintenanceGateway`
备份和还原数据库。后续实现负责复制或打包数据库目录，并恢复 `errDB.db` 中的元数据。

`SecurityGateway`
认证用户、查询权限、断言权限。后续 Controller 或 ApplicationService 在执行 DDL/DML 前调用该接口。

`ClientSessionRegistry`
登记客户端会话、切换当前数据库、注销会话、查询在线客户端。适合后续桌面客户端或多连接管理。

## 5. 一条完整业务流

以 `POST /api/sql/execute` 执行 `SELECT ID, NAME FROM USERS WHERE ID = 1` 为例：

1. `SqlController` 接收 JSON 请求，读取 `databaseName` 和 `sql`。
2. `SqlApplicationService` 去掉尾部分号，调用 `EngineCapabilityPolicy` 做 SQL 白名单校验。
3. `SqlParser` 把 SQL 字符串解析成 `SqlCommand.Select`，其中包含表名、投影列、过滤条件、排序和分页信息。
4. `SqlExecutor` 根据命令类型路由到 `RecordApplicationService`。
5. `RecordApplicationService` 通过 `DatabaseDomainService` 校验数据库名和表名，再调用 `RecordGateway`。
6. `NativeRecordGatewayImpl` 读取 `[表名].tdf` 获得字段布局，扫描 `[表名].trd`，返回符合条件的记录。
7. `SqlExecutor` 在应用层补充复杂过滤、排序、投影列组装，并生成前端表格结构。
8. `SqlController` 用 `ApiResponse` 返回统一响应。

## 6. 后续开发规则

1. 新功能先确认所属模块，不跨模块直接访问别人的 `infrastructure`。
2. 跨模块调用优先调用对方 `application` 服务或 `domain` 接口。
3. 底层文件格式只允许对应模块的 `infrastructure` 修改。
4. 每新增一个接口方法，必须写清楚作用、参数、返回值和异常边界。
5. 每新增一条 SQL 语法，需要同步更新 `SqlCommand`、`SqlParser`、`SqlExecutor` 和本说明文档。
