# 数据库管理系统软件需求

## 1. 引言

### 1.1 目的
本文档旨在描述数据库管理系统的功能和性能需求。预期读者为：用户、项目管理人员、测试人员、设计人员、开发人员。文档明确了软件应具有的功能、性能与界面，使相关人员能清楚了解用户需求。

### 1.2 范围
本文档从用户角度分析数据库管理系统的逻辑模型，解决系统“做什么”的问题，涵盖系统将提供的各种功能及服务。本文档不涉及具体开发技术。

## 2. 总体概述

### 2.1 软件概述

#### 2.1.1 项目介绍
数据库管理系统(DBMS)是一种用于建立、使用和维护数据库的大型软件。它对数据库进行统一管理和控制，以保证其安全性和完整性。用户通过 DBMS 访问数据，数据库管理员通过 DBMS 进行维护。系统支持多个应用程序和用户以不同方法同时或不同时地建立、修改和询问数据库。大部分 DBMS 提供 DDL 和 DML，供用户定义数据库模式与权限约束，实现数据操作。

#### 2.1.2 产品环境
本系统是 Windows 桌面程序，数据存储使用操作系统的文件系统，能通过网络实现客户端与服务端的通讯。

### 2.2 软件功能
系统实现了关系数据库管理系统的基本功能，主要分为以下子模块：

| 系统名称 | 模块名称 | 模块描述 |
| :--- | :--- | :--- |
| 数据库管理系统 | 数据库管理 | 完成数据库的创建与删除功能，实现数据库定义文件的创建、修改与查询。 |
| | 表管理 | 完成表的添加、修改与删除功能，实现表定义文件的创建、修改与查询。 |
| | 字段管理 | 完成表字段的添加、修改与删除功能，实现表字段定义文件的创建、修改与查询。 |
| | 数据管理 | 实现数据的存储、更新、修改与查询的功能。 |
| | 索引管理 | 实现对数据库表中重点字段建立索引，在数据的操作中使用索引进行查询优化。 |
| | 客户端管理 | 实现客户端与服务端结构，客户端可连接多个服务器，服务器可为多个客户端提供服务。 |
| | 事务管理 | 实现数据库中事务管理的功能。 |
| | 完整性管理 | 实现数据库完整性约束的检查与管理功能。 |
| | 数据库维护 | 实现数据库的备份与还原功能。 |
| | 安全性管理 | 实现用户管理、权限管理。 |

### 2.3 用户特征
- **数据库管理员**：具有一定数据库管理知识，能进行数据库的安装、部署、创建、管理与维护。
- **客户端用户**：具备一定应用软件操作和数据库知识，能使用本数据库实现数据的存储、修改、查询等功能。

### 2.4 假设和依赖关系
系统一般情况下使用 Windows 操作系统，特殊情况下应具备可移植条件。

### 3.2 数据库管理

#### 3.2.1 创建数据库
- **介绍**：实现数据库的创建功能。对应 SQL：`CREATE DATABASE <database name>`。数据库分为用户数据库与系统数据库（如 Ruanko，不可删除）。
- **输入**：数据库名称，数据库数据文件存储路径，数据库创建时间，数据库类型。
- **处理**：
    1. 校验数据库名称（长度 ≤128 字符，且不存在）。
    2. 保存数据库信息到 `ruanko.db` 文件（不存在则创建，存在则追加）。
- **输出**：创建或更新 `ruanko.db` 文件。

#### 3.2.2 删除数据库
- **介绍**：实现数据库的删除功能。对应 SQL：`DROP DATABASE <database name>`。系统数据库（如 Ruanko）不可删除。
- **输入**：数据库名称，数据库数据文件存储路径，数据库创建时间，数据库类型。
- **处理**：
    1. 校验数据库是否存在且未被使用。
    2. 从 `ruanko.db` 文件中删除数据库信息。
    3. 删除数据库相关的所有文件。
- **输出**：更新 `ruanko.db` 文件，删除数据库相关文件。

### 3.3 表管理

#### 3.3.1 创建表
- **介绍**：实现数据库表的创建功能。对应 SQL：`CREATE TABLE <table name>`。表信息添加到 `[数据库名称].tb` 文件。
- **输入**：数据库名称，表名称，相关文件路径，创建时间等。
- **处理**：
    1. 校验表名称（长度 ≤128 字符，且不存在）。
    2. 生成表定义文件(`.tdf`)、完整性文件(`.tic`)、记录文件(`.trd`)、索引文件(`.tid`)路径。
    3. 保存表信息到 `[数据库名称].tb` 文件。
- **输出**：创建或更新 `[数据库名称].tb` 文件。

#### 3.3.2 修改表
- **介绍**：修改表信息。对应 SQL：`ALTER TABLE <table name> ...`。
- **处理**：更新表描述文件 `[数据库名称].tb` 中的相应条目。
- **输出**：更新 `[数据库名称].tb` 文件。

#### 3.3.3 删除表
- **介绍**：删除表。对应 SQL：`DROP TABLE <table name>`。
- **处理**：从 `[数据库名称].tb` 中删除表信息，并删除该表对应的所有文件 (`.tdf`, `.trd`, `.tid`, `.tic`)。
- **输出**：更新 `[数据库名称].tb` 文件，删除表相关文件。

### 3.4 字段管理

#### 3.4.1 添加字段
- **介绍**：在表中添加字段。对应 SQL：`ALTER TABLE <table name> ADD COLUMN ...`。
- **处理**：
    1. 校验字段名有效性。
    2. 更新表定义文件 `[表名].tdf`。
- **输出**：创建或更新 `[表名].tdf`。

#### 3.4.2 修改字段
- **介绍**：修改字段信息。对应 SQL：`ALTER TABLE <table name> MODIFY COLUMN ...`。
- **处理**：
    1. 校验字段存在性。
    2. 更新 `[表名].tdf` 中的字段信息。
    3. 如有记录，更新全部记录及索引。
- **输出**：更新 `.tdf`, `.trd`, `.tid` 文件。

#### 3.4.3 删除字段
- **介绍**：删除字段。对应 SQL：`ALTER TABLE <table name> DROP COLUMN ...`。
- **处理**：
    1. 校验字段存在性。
    2. 若字段被索引使用，移除相关索引。
    3. 更新 `[表名].tdf`。
    4. 如有记录，更新全部记录。
- **输出**：更新 `.tdf`, `.trd`, `.tid` 文件。

### 3.5 数据管理

#### 3.5.1 插入记录
- **介绍**：插入记录。对应 SQL：`INSERT INTO ...`。
- **处理**：
    1. 读取字段记录，检查完整性约束。
    2. 给自增与默认字段赋值。
    3. 保存记录到 `[表名].trd` 文件。
- **输出**：写入 `[表名].trd` 文件。

#### 3.5.2 更新记录
- **介绍**：更新记录。对应 SQL：`UPDATE ... SET ...`。
- **处理**：
    1. 检查完整性约束。
    2. 定位并更新记录文件 `[表名].trd`。
- **输出**：更新 `[表名].trd` 文件。

#### 3.5.3 查询记录
- **介绍**：查询记录。对应 SQL：`SELECT ... WHERE ...`。
- **处理**：读取表信息，返回符合条件的记录。
- **输出**：在界面视图中显示记录。

#### 3.5.4 删除记录
- **介绍**：删除记录。对应 SQL：`DELETE FROM ... WHERE ...`。
- **处理**：
    1. 定位要删除的记录。
    2. 更新记录文件 `[表名].trd` 和索引文件 `[表名].tid`。
- **输出**：更新 `.trd` 和 `.tid` 文件。

### 3.12 数据字典

#### 3.12.1 数据类型
| DBMS 类型 | 说明 | 大小 | 程序类型 |
| :--- | :--- | :--- | :--- |
| INTEGER | 整数 | 4 byte | int |
| BOOL | 布尔类型 | 1 byte | bool |
| DOUBLE | 浮点数 | 2 byte | double |
| VARCHAR | 变长字符串 varchar(n)，最长 255 字符，以`\0`结尾 | (n+1) byte | char[n+1] |
| DATETIME | 日期时间类型 | 16 byte | SYSTEMTIME |

#### 3.12.2 完整性
- **实体完整性**: `PRIMARY KEY`
- **参照完整性**: `FOREIGN KEY`
- **自定义完整性**: `CHECK`, `UNIQUE`, `NOT NULL`, `DEFAULT`, `IDENTITY`

#### 3.12.3 数据库文件
约定：`DBMS_ROOT` 为程序安装根目录。所有数据以二进制文件存储。

- **数据库描述文件**: `/DBMS_ROOT/ruanko.db`
- **数据库文件夹**: `[DBMS_ROOT]/data/[数据库名称]/`，包含：
    - 表描述文件: `[数据库名称].tb`
    - 日志文件: `[数据库名称].log`
- **表文件**（在数据库文件夹下）:
    - 表定义文件: `[表名].tdf`
    - 记录文件: `[表名].trd`
    - 完整性描述文件: `[表名].tic`
    - 索引描述文件: `[表名].tid`
- **索引数据文件**: `[索引名].ix` (索引名格式：`[字段名]Index`)

#### 3.12.4 数据库描述文件 (`ruanko.db`)
二进制文件，包含一个或多个数据库块 (`DatabaseBlock`)，结构如下：
| 结构体成员 | 数据类型 | 说明 |
| :--- | :--- | :--- |
| name | CHAR[128] | 数据库名称 |
| type | BOOL | 数据库类型 (系统/用户) |
| filename | CHAR[256] | 数据库数据文件夹全路径 |
| crtime | DATETIME | 创建时间 |

#### 3.12.5 表描述文件 (`[数据库名].tb`)
二进制文件，包含一个或多个表格块 (`TableBlock`)，结构如下：
| 结构体成员 | 数据类型 | 说明 |
| :--- | :--- | :--- |
| name | CHAR[128] | 表格名称 |
| record_num | INTEGER | 记录数 |
| field_num | INTEGER | 该表字段数 |
| tdf | CHAR[256] | 表格定义文件路径 |
| tic | CHAR[256] | 表格完整性文件路径 |
| trd | CHAR[256] | 表格记录文件路径 |
| tid | CHAR[256] | 表格索引文件路径 |
| crtime | DATETIME | 创建时间 |
| mtime | INTEGER | 最后修改时间 |

#### 3.12.6 表定义文件 (`[表名].tdf`)
二进制文件，包含一个或多个字段块 (`FieldBlock`)，结构如下：
| 结构体成员 | 数据类型 | 说明 |
| :--- | :--- | :--- |
| order | INTEGER | 字段顺序 |
| name | CHAR[128] | 字段名称 |
| type | INTEGER | 字段类型 |
| param | INTEGER | 字段类型参数 (如 VARCHAR 的长度) |
| mtime | DATETIME | 最后修改时间 |
| integrities | INTEGER | 完整性约束信息 |

#### 3.12.7 记录文件 (`[表名].trd`)
二进制文件，按顺序存储记录的物理数据。为提高效率，所有块和字段大小在存储时调整成 4 的倍数。

#### 3.12.8 完整性描述文件 (`[表名].tic`)
二进制文件，包含一个或多个约束块，结构如下：
| 结构体成员 | 数据类型 | 说明 |
| :--- | :--- | :--- |
| name | CHAR[128] | 约束名称 |
| field | CHAR[128] | 字段名称 |
| type | INTEGER | 约束类型 |
| param | CHAR[256] | 参数 |

#### 3.12.9 索引描述文件 (`[表名].tid`)
二进制文件，包含一个或多个索引块 (`IndexBlock`)，结构如下：
| 结构体成员 | 数据类型 | 说明 |
| :--- | :--- | :--- |
| name | CHAR[128] | 索引名称 |
| unique | BOOLEAN | 是否唯一索引 |
| asc | BOOLEAN | 排序方式 (true: ASC, false: DESC) |
| field_num | INTEGER | 索引字段数 (≤2) |
| fields | CHAR[128][2] | 索引字段名 |
| record_file | CHAR[256] | 索引对应记录文件的路径 |
| index_file | CHAR[256] | 索引数据文件的路径 |

- **索引数据文件**: `[索引名].ix`，存储索引数据。
