# 后端与前端/测试任务分工

## 1. 后端负责人：A（模块：索引 + 完整性 + 维护）

### 模块范围
- `index`、`integrity`、`maintenance`（只改各自的 `application/domain/infrastructure`）

### 主要任务

#### a. Index
- 实现 `CREATE` / `DROP` / `SHOW` / `REBUILD` 索引（如已定义语法）
- 维护 `.tid` / `.ix` 文件的读写与同步

#### b. Integrity
- 实现 `ADD` / `DROP` / `SHOW` / `CHECK` 约束解析
- 实现 `.tic` 文件读写

#### c. Maintenance
- 实现 `BACKUP` / `RESTORE` / `SHOW` / `DELETE` 备份（打包与还原）

### 边界约束
- 不修改 `SqlParser` / `SqlExecutor` / `Controller`（已有路由保持不动）
- 只接触 `index` / `integrity` / `maintenance` 模块内的接口与实现
- 需要的通用工具只放在本模块内部，不抽取公共层

---

## 2. 后端负责人：B（模块：客户端 + 事务 + 安全）

### 模块范围
- `client`、`transaction`、`security`（只改各自的 `application/domain/infrastructure`）

### 主要任务

#### a. Client
- `CONNECT` / `DISCONNECT` / `SHOW CLIENTS`
- 会话管理与状态保存

#### b. Transaction
- `BEGIN` / `COMMIT` / `ROLLBACK`
- 日志与回滚逻辑（先实现单会话）

#### c. Security
- `CREATE` / `DROP` / `ALTER USER`
- `GRANT` / `REVOKE` / `SHOW GRANTS`
- 权限校验

### 边界约束
- 不修改 `SqlParser` / `SqlExecutor` / `Controller`
- 不修改 `index` / `integrity` / `maintenance` 模块代码
- 安全校验仅在 `security` 模块内实现，并通过接口注入

---

## 3. 前端负责人：C（页面设计 + 统一 `/api/sql/execute`）

### API 设计规则
- 所有请求统一使用 `POST /api/sql/execute`
- 请求体格式：
  ```json
  {
    "databaseName": "<数据库名>",
    "sql": "<SQL语句>"
  }
  ```
- `dbms.js` 内提供语义函数，只负责拼接 SQL 字符串并调用 `executeSql`

### 需要新增 / 完善的页面

#### 用户与权限管理页
- 用户列表
- 权限授予 / 撤销
- `SHOW GRANTS`

#### 客户端会话管理页
- `CONNECT`
- `DISCONNECT`
- `SHOW CLIENTS`

### 交付要求
- 页面只负责：
  - 收集参数
  - 拼接 SQL
  - 展示结果表格
- 不新增 REST 路径
- 不做多接口调用

---

## 4. 测试负责人：D（独立测试，不改业务代码）

### 测试范围

#### SQL-only 流程
- 每个模块的命令是否可执行
- 响应结构是否正确

#### 回归测试
- 数据库 / 表 / 字段 / 记录的基础功能不被新模块影响

### 测试用例建议

| 模块 | 测试内容 |
|------|----------|
| Index | 创建 / 删除 / 重建 / 查询索引；插入 / 更新后索引一致性 |
| Integrity | 添加约束后插入 / 更新是否阻止非法数据 |
| Maintenance | 备份文件生成、还原后数据一致 |
| Client | 多客户端连接与断开，`SHOW CLIENTS` 数据准确 |
| Transaction | `BEGIN` 后写入、`ROLLBACK` 回退、`COMMIT` 落盘 |
| Security | 权限不足时阻止操作，授予后放行 |

### 输出要求
- 测试清单
- 结果记录（成功 / 失败 / 复现步骤）

---

## 5. 交叉依赖说明（避免互改）

- 后端 **A** 只改 `index` / `integrity` / `maintenance`
- 后端 **B** 只改 `client` / `transaction` / `security`
- 若发现 `Parser` / 路由缺失，**只报问题，不擅自修改**（由负责人共同确认后再处理）
- 前端只改 `dbms.js` 与页面，**不修改后端**
- 测试**不修改代码**，仅提交问题与复现步骤
