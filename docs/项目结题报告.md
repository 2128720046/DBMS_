## a) 技术方案设计

### 一、整体架构

系统采用 **前后端分离 + 模块化单体后端** 架构。前端为 Vue 3 SPA，后端为 Spring Boot 单体应用，前后端通过唯一的 REST 接口 `POST /api/sql/execute` 通信。

```
┌─────────────────────┐      HTTP/JSON       ┌──────────────────────────┐
│   Vue 3 Frontend    │──────────────────────→│  Spring Boot Backend     │
│                     │  POST /api/sql/execute│                          │
│  Element Plus UI    │←──────────────────────│  自研二进制存储引擎      │
│  SQL 拼接层         │     {code,message,data}                         │
└─────────────────────┘                       └──────────────────────────┘
```

### 二、后端架构

#### 2.1 模块化单体结构

后端按业务能力拆分为 10 个独立模块，公共能力抽取到 `core` 和 `common`：

```
com.dbms.backend
├── common                  # 统一响应 (ApiResponse)、错误码、全局异常处理
├── core                    # 跨模块基础能力
│   ├── capability          # 引擎功能开关与 SQL 白名单
│   ├── naming              # 标识符校验
│   └── storage             # 二进制文件 I/O 工具与存储路径配置
└── modules                 # 10 个业务模块
    ├── sql                 # SQL 解析 (SqlParser) + 执行路由 (SqlExecutor)
    ├── database            # 数据库生命周期管理
    ├── table               # 表与字段定义管理
    ├── record              # 记录增删改查
    ├── index               # 索引管理（B+ 树）
    ├── integrity           # 完整性约束管理
    ├── transaction         # 事务管理
    ├── maintenance         # 备份恢复
    ├── security            # 用户与权限
    └── client              # 客户端会话
    └── log                 # 请求日志
```

#### 2.2 请求处理流程

```
浏览器 → POST /api/sql/execute
  → SqlController
    → SqlApplicationService (去分号 + 白名单校验 + token 解析)
      → SqlParser (SQL 字符串 → SqlCommand 结构化命令)
        → SqlExecutor (路由到对应模块)
          → ApplicationService
            → Gateway 接口
              → GatewayImpl (二进制文件 I/O)
                → 返回 Map<String,Object> 结果
```

#### 2.3 各模块职责

| 模块 | 职责 | 核心接口 |
|------|------|---------|
| `sql` | SQL 解析与执行路由 | SqlParser / SqlExecutor |
| `database` | 数据库创建、删除、列表 | DatabaseSchemaGateway |
| `table` | 表结构 CRUD | TableGateway |
| `record` | 数据记录增删改查 | RecordGateway |
| `index` | 索引生命周期 + B+ 树 | IndexGateway |
| `integrity` | 约束注册与校验 | IntegrityGateway |
| `transaction` | 事务 begin/commit/rollback | TransactionManagerPort |
| `maintenance` | 备份打包与还原 | MaintenanceGateway |
| `security` | 用户注册、认证、授权 | SecurityGateway |
| `client` | 客户端会话管理 | ClientSessionRegistry |

#### 2.4 二进制存储文件体系

所有数据存储在 `data/` 目录下，每个数据库对应一个子目录：

| 文件后缀 | 全称 | 用途 |
|---------|------|------|
| `.tdf` | Table Definition File | 列定义（顺序、类型、完整性标志） |
| `.trd` | Table Record Data | 行数据记录（二进制定长） |
| `.tic` | Table Integrity Constraints | 完整性约束描述 |
| `.tid` | Table Index Description | 索引描述 |
| `.ix` | Index Data File | B+ 树索引数据 |

| `errDB.db` | System Catalog | 系统全局数据库目录 |
| `system_users.dat` | User Data | 用户与权限的 JSON 持久化 |

### 四、认证与权限体系

```
用户登录 → CONNECT → 后端认证 → 返回 token + clientId
   ↓
后续请求携带 token → 后端 resolveUser(token) → 获取 username
   ↓
assertPermission(username, db, table, 权限类型) → 检查用户权限
   ↓
权限不足 → 抛出 IllegalArgumentException("用户 'xxx' 没有权限")
```

- 内置管理员 `admin/admin123`，拥有所有权限
- 新注册用户自动获得 `SELECT ON *.*` 权限
- 管理员可通过 GRANT/REVOKE 管理普通用户权限
- 权限持久化存储在 `system_users.dat`

## b) 关键算法实现描述

### 一、SQL 解析器（SqlParser）

#### 1.1 解析流程

```
原始 SQL 字符串
    ↓ 去除末尾分号
    ↓ 关键词前缀匹配（SELECT / INSERT / CREATE / ...）
    ↓ 按命令类型调用专用解析方法
    ↓ 返回 SqlCommand 密封记录
```

解析器支持 40+ 种 SQL 命令类型，覆盖数据库管理、表管理、DML、索引、约束、事务、备份、安全、客户端等全部模块。

#### 1.2 列定义解析

```
输入: "name VARCHAR(64) NOT NULL UNIQUE CHECK (name != '') REFERENCES dept(id)"
输出: ColumnDefinition { name, type, length, nullable, pk, uq, checkExpression, foreignKeyTable, foreignKeyColumn }
```

通过分词扫描，依次识别类型、长度、约束关键字，并提取内联的 CHECK 表达式和 REFERENCES 外键引用。

#### 1.3 SELECT 语句解析

支持完整的 SQL 语义分解：

```
SELECT [投影列] FROM 表名 [JOIN 表名 ON 条件] [WHERE 条件] [ORDER BY 列 [ASC|DESC]] [LIMIT [偏移,] 数量]
    ↓
SelectCommand { tableName, projection[], filters, orderBy[], limit, joins[] }
```

### 二、执行引擎（SqlExecutor）

#### 2.1 路由算法

采用 `instanceof` 模式匹配路由到 40+ 种命令：

```
SqlCommand 实例
    ├── ShowDatabases → 遍历数据库目录
    ├── Select → 全表扫描 / 索引查找 → 过滤 → 排序 → 分页
    ├── Insert → 逐列序列化 → 追加写入 .trd
    ├── Update → 逐行匹配 → 覆盖写入 .trd
    ├── Delete → 逐行匹配 → 逻辑删除（状态位置 0）
    ├── CreateTable → 写入 .tb + .tdf → 创建空 .trd/.tic/.tid/.ix
    ├── AlterTable → 重写 .tdf + 迁移 .trd 数据
    ├── ...
```

#### 2.2 权限校验拦截

在执行任何 DML/DDL 前，先通过 `assertPermission()` 检查用户权限：

```
execute(token)
  → resolveUser(token) → username
  → assertPermission(username, db, table, "SELECT")  // 查询
  → assertPermission(username, db, table, "INSERT")  // 插入
  → assertPermission(username, db, table, "UPDATE")  // 更新
  → assertPermission(username, db, table, "DELETE")  // 删除
  ...
  → assertAdmin(username, "CREATE USER")             // 用户管理 (仅admin)
```

### 三、B+ 树索引（BPlusTreeIndex）

```
class BPlusTreeIndex {
    int order;         // B+ 树阶数
    boolean unique;    // 是否唯一索引
    boolean ascending; // 是否升序
    Node root;         // 根节点
    List<FieldMeta> keyMetas; // 索引字段元数据
    
    class Node {
        long id;
        boolean leaf;          // 是否为叶子节点
        List<List<Object>> keys; // 键列表
        List<Long> children;    // 子节点 ID（内部节点）
        List<Long> offsets;    // 记录偏移量（叶子节点）
        long nextLeafId;       // 下一个叶子节点 ID（叶节点链）
    }
}
```

#### 索引持久化

```
build(entries) → 构造 B+ 树 → save(ixFile) → 写入二进制 .ix 文件
load(ixFile)  → 读取 .ix 文件 → 重建 B+ 树 → searchEquals(key) → recordOffsets[]
```

#### 索引查询优化

```
SELECT * FROM employee WHERE dept_id = 1
  → 检查 .tid 中是否有 dept_id 索引
  → 加载 .ix B+ 树
  → tree.searchEquals([dept_id=1]) → [recordOffset1, recordOffset2, ...]
  → 直接定位 .trd 读取指定行，避免全表扫描
```

### 四、完整性约束校验

#### 4.1 约束类型与校验算法

| 约束类型 | 校验时机 | 校验算法 |
|---------|---------|---------|
| NOT NULL | INSERT/UPDATE | 值是否为 null 或空字符串 |
| PRIMARY KEY | INSERT/UPDATE | 值不为空 + 全表扫描检查重复 |
| UNIQUE | INSERT/UPDATE | 全表扫描检查重复值 |
| CHECK | INSERT/UPDATE | 解析 CHECK 表达式 → 比较操作符求值 |
| FOREIGN KEY | INSERT/UPDATE | 检查引用表中是否存在对应值 |
| 参照完整性 | DELETE | 扫描其他表的外键是否引用当前行 |

#### 4.2 CHECK 表达式求值

```
输入: "CHECK (age >= 18)"
  → parseCheckExpression: column="age", operator=">=", literal="18"
  → matchCheckExpression:
      value = row.get("age")
      if value == null → return true (SQL 标准 UNKNOWN 语义)
      literal = parseLiteral("18") → 18 (number)
      cmp = compareValue(value, literal)
      operator ">=" → return cmp >= 0
```

### 五、事务回滚实现

采用 **undo 日志栈** 模式：

```
BEGIN
  → 生成事务 ID (txId)
  → 创建空撤销栈
INSERT/UPDATE/DELETE
  → 记录撤销操作 (Runnable) 到 undo 栈
COMMIT
  → 清空 undo 栈 → 保留数据变更
ROLLBACK
  → 逆序执行 undo 栈 → 依次撤销每条变更 → 清空栈
```

### 六、二进制存储格式

#### 6.1 表定义文件 (.tdf)

每个字段 160 字节定长块：

```
[4字节 order] [128字节 name] [4字节 typeCode] [4字节 param] [16字节 mtime] [4字节 integrity]
```

`integrity` 位标志：bit0=NOT_NULL, bit1=PK, bit2=UNIQUE

#### 6.2 记录数据文件 (.trd)

```
[4字节 status] [payload: 按 .tdf 定义的字段顺序连续存储]
status=1 表示有效行，status=0 表示逻辑删除行
```

每个字段按类型定长存储，不足部分 4 字节对齐填充。
