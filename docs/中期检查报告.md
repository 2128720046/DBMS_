## 二、项目方案设计
### 2.1 项目总体方案
项目面向课程设计场景，采用 B/S 架构实现一个教学型数据库管理系统。系统以数据库、表、字段、记录、索引、完整性、备份恢复和安全管理为主要功能对象，通过前端页面完成用户交互，通过后端服务完成业务编排、规则校验与文件持久化。

项目方案沿用初期立项书的分层思路，并在中期进一步细化为“界面层、应用层、业务层、支撑层”四层结构。界面层负责页面展示与交互；应用层负责请求接入与流程编排；业务层负责核心规则与模块协作；支撑层负责文件读写、备份恢复、统一异常处理与系统配置。

### 2.2 系统架构设计
系统采用前后端分离方式构建：
- 前端采用 Vue 3 + Vite 组织页面、路由和状态交互。
- 后端采用 Spring Boot 负责接口、业务编排和统一返回。
- 数据持久化采用文件系统组织方式，按数据库、表、字段、记录与索引维度拆分存储。
- 所有功能通过统一 HTTP 接口对外提供，返回结构保持一致，便于前端快速集成与演示。

系统内部采用“控制器 -> 应用服务 -> 领域规则 -> 存储服务”的调用链路。控制器负责参数接入，应用服务负责流程组织，领域层负责命名规则与约束验证，存储层负责结构文件与数据文件的维护。该设计保证核心功能职责清晰，也便于后续继续扩展事务、权限和日志能力。

### 2.3 文件存储方案设计
根据项目要求，系统数据统一以文件形式组织，形成“数据库级目录 + 表级文件”的结构化存储方案。当前方案已经按照以下思路实现：
- 每个数据库对应独立目录，数据库描述信息写入数据库级描述文件。
- 每个表对应独立的表定义文件、记录文件、完整性文件和索引文件。
- 数据库创建、表创建、字段调整、删除等操作均会同步更新对应文件。

文件组织强调两点：一是结构清晰，便于按对象定位；二是元数据与数据文件分离，便于后续扩展恢复、检查和导出能力。该方案与项目需求中的对象层级一致，能够支撑中期之后的功能继续拓展。

### 2.4 接口与页面设计
系统接口按资源划分，数据库、表、记录、索引、完整性、备份与登录均有独立路由。页面层按功能拆分为数据库管理、表管理、字段管理、记录管理、SQL 控制台、索引与约束、备份恢复、系统设置等模块，便于各功能独立演示和联调。

前端页面强调“可视化操作 + 结果即时反馈”的交互方式，尽量减少用户对命令行的依赖，保证课程演示过程直观、清晰、稳定。

## 四、后续功能实现计划
### 4.1 后续开发重点
后续阶段将重点补齐以下能力：
- 事务管理：补充事务开始、提交、回滚和异常恢复流程。
- 安全管理：完善用户、角色与权限控制策略。
- 完整性增强：进一步完善外键、多字段约束和冲突处理逻辑。
- 记录与索引协同：加强记录变更时的索引更新一致性。
- 文件结构细化：完善各类描述文件的字段对齐和状态更新机制。
- 运维增强：补充备份恢复的历史版本管理与恢复确认流程。

### 4.2 后续阶段安排
第 1 阶段，优先补齐事务与权限控制，使系统具备更完整的操作保护能力。

第 2 阶段，完善完整性规则与索引维护，提升数据一致性与查询稳定性。

第 3 阶段，细化文件结构与恢复机制，增强系统可维护性和可演示性。

第 4 阶段，集中联调、测试与文档整理，完善中后期提交材料和答辩展示内容。

### 4.3 风险与控制措施
- 若某模块开发进度滞后，优先保证数据库、表、记录三条主线不受影响。
- 若联调出现接口不一致，先统一请求/响应结构，再处理页面细节。
- 若文件结构调整影响范围较大，先固定元数据格式，再逐步扩展字段定义。
- 若后续功能实现时间紧张，优先保留可演示主流程，次级增强功能可按优先级延后。
