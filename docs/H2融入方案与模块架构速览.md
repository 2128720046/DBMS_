# H2 融入方案与模块架构速览

## 1. 现状结论（先看这个）
当前仓库中的 H2 代码是完整内核源码副本，位置在 `backend/src/main/h2`，规模接近完整数据库实现。

但当前 Maven 构建并不会自动编译 `src/main/h2`：
- 构建文件仅包含标准 Java 源码目录，见 [backend/pom.xml](../backend/pom.xml)
- 没有 `build-helper-maven-plugin` 或其他额外 sourceDirectory 配置
- 实际运行使用的是 Maven 依赖中的 H2 驱动，见 [backend/pom.xml](../backend/pom.xml)

所以现在 `backend/src/main/h2` 更像“参考源码”，而不是你项目运行时真正执行的代码。

## 2. H2 模块架构（按包职责速览）
H2 主要是一个 SQL 数据库内核，核心模块可按以下方式理解：

- `engine`：数据库生命周期、会话、权限、事务隔离等核心引擎能力
- `command`：SQL 解析后的命令对象（DDL/DML 执行入口）
- `expression`：表达式树与计算逻辑（条件、函数、运算）
- `table`：表结构、列定义、视图与表相关元数据
- `index`：索引接口与实现、游标、范围扫描
- `constraint`：主键、外键、唯一、检查约束
- `mvstore`：底层存储引擎（页、事务版本、文件存储）
- `jdbc` / `jdbcx`：JDBC 协议层
- `tools`：脚本、备份恢复、控制台等工具

你可以把 H2 理解成“已经实现好的数据库内核 + SQL 执行器”。

## 3. 你项目当前后端架构（可直接复用 H2 的接入点）
当前后端已经有分层和 SPI 结构，接入点很清晰：

- 控制器： [backend/src/main/java/com/dbms/backend/controller/DatabaseController.java](../backend/src/main/java/com/dbms/backend/controller/DatabaseController.java)
- 应用服务： [backend/src/main/java/com/dbms/backend/application/DatabaseApplicationService.java](../backend/src/main/java/com/dbms/backend/application/DatabaseApplicationService.java)
- 领域规则： [backend/src/main/java/com/dbms/backend/domain/DatabaseDomainService.java](../backend/src/main/java/com/dbms/backend/domain/DatabaseDomainService.java)

## 4. 推荐融入路径（按投入产出排序）

### 路径 A（最推荐，最快落地）
使用 H2 作为嵌入式数据库引擎，通过 JDBC + Spring Boot 封装 REST API。

你们要做的是：
- 继续写业务接口（Controller/Application/Domain）
- 在 Infrastructure 层把 SQL 封装成网关实现
- 让前端通过 REST 调接口

你们不用做的：
- 不需要自己实现 SQL 解析器
- 不需要自己实现事务日志引擎
- 不需要自己实现 B+ 树索引内核

### 路径 B（不建议，维护成本高）
直接修改 `src/main/h2` 的源码并作为你项目内核。

问题：
- 升级和维护成本高
- 调试困难
- 课程项目周期内收益低

### 路径 C（折中）
保留 H2 作为执行引擎，同时在你自己的 Domain 层做“规则与审计增强”。

例如：
- SQL 黑白名单
- 权限策略
- 操作审计日志
- 业务约束前置校验

## 5. 让“后端功能模块不用自己实现”的可执行清单
你们可以只实现“业务外壳”，底层交给 H2：

1. 数据库与表管理：
- `CREATE SCHEMA`
- `CREATE TABLE`
- `DROP ...`

2. 记录增删改查：
- `INSERT / UPDATE / DELETE / SELECT`

3. 索引与约束：
- `CREATE INDEX`
- `PRIMARY KEY / UNIQUE / FOREIGN KEY`

4. 事务：
- JDBC 事务控制（提交/回滚）

5. 备份恢复（可选）
- 使用 H2 工具或脚本能力

## 6. 你现在最应该做的三件事
1. 保留 `src/main/h2` 作为参考，不把它当主开发区。
2. 在现有 SPI 网关中逐步补齐 SQL 版本实现（先数据库、再表、再记录）。
3. 增加 SQL 执行接口（你已经规划了 SQL 控制台），由后端统一执行并返回标准结果。

## 7. 风险提醒
- 当前 `application.yml` 使用的是内存库：`jdbc:h2:mem:testdb`，重启会丢数据。
- 若要演示稳定，建议切到文件库模式（例如 `jdbc:h2:file:./data/testdb`）。

## 8. 一句话建议
你的目标不是“造一个数据库内核”，而是“做一个可用 DBMS 应用层产品”。
所以最优策略是：H2 做内核，你们做管理平台与业务规则。
