# 测试文档

> 使用 Swagger UI: `http://localhost:8080/swagger-ui/index.html`
> 接口: `POST /api/sql/execute`
> 请求体: `{ "databaseName": "", "sql": "..." }`

---

## 测试集 A：用户管理与认证（B 已实现，无需 A 配合）

### A1. 创建用户

```json
{ "databaseName": "", "sql": "CREATE USER 'testuser' IDENTIFIED BY 'pass123'" }
```
预期返回：`"用户创建成功"`

### A2. 用户持久化验证

1. 重启 Spring Boot 应用
2. 重新用刚创建的用户登录：

```json
{ "databaseName": "", "sql": "CONNECT TO mydb PORT 3306 USER 'testuser' IDENTIFIED BY 'pass123'" }
```
预期返回：包含 `clientId`、`username`、`token` 的连接成功信息

### A3. 查询权限

```json
{ "databaseName": "", "sql": "SHOW GRANTS FOR 'testuser'" }
```
预期返回：空权限列表

## 测试集 B：会话管理（B 已实现，需 A 路由后激活）

### B1. 查询在线客户端

```json
{ "databaseName": "", "sql": "SHOW CLIENTS" }
```
> **当前返回**：只有 `CLIENT_ID` 一列
> **A 路由后**：返回 `CLIENT_ID, USER, IP_ADDRESS, PORT, CONNECTED_AT, CURRENT_DATABASE`

### B2. 断开连接

```json
{ "databaseName": "", "sql": "DISCONNECT 693ced99-6694-4572-b4a0-d98f80438ae0" }
```
> **当前返回**：`"连接已断开"`（但未清理会话）
> **A 路由后**：实际调用 `disconnect(clientId)` 清理会话

## 测试集 C：安全命令（B 已实现持久化，需 A 路由后激活）

### C1. 删除用户

```json
{ "databaseName": "", "sql": "DROP USER 'testuser'" }
```
> **当前返回**：占位消息
> **A 路由后**：返回 `"用户删除成功"`，同时文件 `system_users.dat` 中移除该用户

### C2. 修改密码

```json
{ "databaseName": "", "sql": "ALTER USER 'testuser' IDENTIFIED BY 'newpass456'" }
```
> **当前返回**：占位消息
> **A 路由后**：密码更新后持久化到 `system_users.dat`

### C3. 授予权限

```json
{ "databaseName": "", "sql": "GRANT SELECT, INSERT ON mydb.* TO 'testuser'" }
```
> **当前返回**：占位消息
> **A 路由后**：权限持久化到 `system_users.dat`

### C4. 撤销权限

```json
{ "databaseName": "", "sql": "REVOKE INSERT ON mydb.* FROM 'testuser'" }
```
> **当前返回**：占位消息
> **A 路由后**：权限变更持久化到 `system_users.dat`

## 测试集 D：事务管理（B 已实现回滚框架，需 Record 模块配合后真正生效）

### 前置：创建数据库

```json
{ "databaseName": "", "sql": "CREATE DATABASE testtx" }
```

### D1. 开启事务

```json
{ "databaseName": "testtx", "sql": "BEGIN" }
```
预期：返回事务 ID（如 `"事务已开启: TESTTX-xxxx-xxxx-xxxx"`）

### D2. 提交事务

```json
{ "databaseName": "testtx", "sql": "COMMIT" }
```
预期：`"事务已提交"`

### D3. 回滚事务

```json
{ "databaseName": "testtx", "sql": "ROLLBACK" }
```
预期：`"事务已回滚"`
> **当前**：只是清除事务标记（空壳）
> **Record 模块配合后**：真正逆序撤销事务内所有数据变更

## 已知限制（待 A 修复后解除）

| # | 症状 | 原因 | 参考 notice.md |
|---|------|------|----------------|
| 1 | DROP USER / ALTER USER / GRANT / REVOKE 返回占位消息 | SqlExecutor 未路由到 SecurityApplicationService | 改动二 |
| 2 | COMMIT / ROLLBACK 传的是库名而非真实事务 ID | 多客户端时可能冲突 | 改动一 |
| 3 | DISCONNECT 未清理会话 | SqlExecutor 未调用 clientApplicationService.disconnect() | 改动四 |
| 4 | SHOW CLIENTS 只返回 CLIENT_ID | SqlExecutor 应改为调用 listOnlineClientDetails() | 改动五 |
| 5 | ROLLBACK 不撤销数据 | Record 模块未接入 recordUndoOperation | 改动三 |
